独立审计严格按预登记 fail-closed，因此总结果是 **FAIL**。失败原因不是
尾缘分支缺失或歧义，而是重跑值没有与旧 JSON 逐 IEEE-754 bit 相等：

- 三个网格各观察到预期的 `33` 次 selector 调用，共 `99` 次；
- 每一次 lower 和 upper 两支都成功返回完整证据；
- 每一次都只有一支满足非零符号规则，且原 selector 选择了该支；
- `p64` 的全部冻结指标逐 bit 相等；
- `p128` 有 11 个量出现末位差，最大绝对差
  `8.88e-16`，非近零量最大相对差 `4.16e-16`；
- `p256` 有 15 个量出现末位差，最大绝对差
  `7.11e-15`，非近零量最大相对差 `1.31e-14`。

因此可作两个彼此分离的判断：

1. **branch 子门补齐并通过。** 原三层运行的上下候选支路确实均被求解，
   不存在“一支报错后仍宣称无歧义”的实际事件。
2. **bitwise 重放门失败。** 稠密线性代数重跑有浮点末位漂移，不能把
   “数值等价”改称“逐 bit 身份”，也不得事后放宽预登记门。

这两个判断都不能逆转 `N2.6e1b1`：其 `7--9%` 局部出生状态非收敛比上述
重放末位差大约 12--14 个数量级，故 `falsified/frozen` 保持不变。
