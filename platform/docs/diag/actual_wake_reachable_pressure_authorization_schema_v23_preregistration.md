### 0.1 `NamespaceProfileV1` 与唯一 path algorithm

同一 private parser 接受一个显式 typed profile，而不是读取 ticket 自报的
filesystem authority。profile不是 JSON artifact。所有 directory authority
只能由以下 opaque typed lease 表达：

```text
_DirectoryLeaseV1 exact fields:
  absolute_path: absolute Path
  fd: nonnegative integer, not bool
  st_dev: nonnegative integer, not bool
  st_ino: positive integer, not bool
  owner_created: exact bool
```

lease 的 `fd` 必须仍 open，`FD_CLOEXEC` 为 true，`fstat(fd)` 必须是 directory
且 identity exact 等于 `(st_dev,st_ino)`；`absolute_path` fresh
`O_RDONLY|O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC` reopen也必须得到同一 identity。
lease class constructor不对 caller开放；只有本节两个 factory能返回实例。

`NamespaceProfileV1` 是 discriminated typed union，而不是一个可自由填 map：

```text

  mode
  repo_root_lease
  implementation_identity_core_path
  issuance_request_path
  ticket_path
  result_path
  marker_path
  allowed_trace_root
  production_credential_allowed

_FixtureNamespaceProfileV1 exact fields:

  repo_root_lease
  fixture_base_lease
  isolation_root_lease
  fixture_id
  implementation_identity_core_path
  issuance_request_path
  ticket_path
  result_path
  marker_path
```

`isolation_root := isolation_root_lease.absolute_path`。所有 `*_path` 是 absolute

`not(F <=p R)` 且 `not(R <=p F)`。这是一条双向 component-prefix不可比规则，

在 fixture 内：

- 五个 file paths
  `implementation_identity_core/issuance_request/ticket/result/marker` 必须是
  isolation root 的 strict descendants，pairwise component-prefix不可比；
- `allowed_trace_root` 必须是 isolation root 的 strict descendant directory，
  并与上述五个 file paths双向 component-prefix不可比；
- Q 的 observed path 必须 exact 等于 `issuance_request_path`；
- M/A/C/Z 必须是 `allowed_trace_root` 的 strict descendants并满足第 4.3 节；
- 所有其他 synthetic artifact path必须是 isolation root的 strict descendant。

fixture 只允许 definition tests、G2/G3 no-history controls和 G6 publisher fault
fixtures；formal collector/mesh/march calls 必须为 0。它不能生成 production
credential，也不能让 public `_load_and_verify_authorization()` 返回。public
adapter 必须构造 production profile；tests/G3 直接调用同一 private seam并显式
传 fixture profile。这不是 monkeypatch parser、跳过字段或使用第二个 parser。

JSON 内所有 repo-relative path 的唯一算法：

1. 输入必须是 nonempty UTF-8 string，无 NUL、反斜杠或
   `*`/`?`/`[`/`]`；
2. `PurePosixPath(value)` 必须非 absolute，且 `value == pure.as_posix()`；
3. 每个 component 必须不为空且不属于 `.`/`..`；
4. lexical absolute target 只按 `repo_root.joinpath(*pure.parts)` 构造，不
   `resolve()`、不 `normpath()`、不做 alternate basename选择；
5. profile factory只以
   `os.open(repo_root, O_RDONLY|O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC)` 建立
   `repo_root_lease`；`lstat(repo_root)` 必须是 directory且其
   `(st_dev,st_ino)` exact 等于 lease。seam不按 path另猜 root，而是验证并使用
   lease fd。所有 parent component 从相应 root/isolation lease fd逐级
   `O_RDONLY|O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC`，final read使用
   `O_RDONLY|O_NOFOLLOW|O_CLOEXEC`；
6. profile/root/path 的 lexical相对关系在相同 component tuples上判断；
7. 任一 symlink、root inode漂移、非 regular final file或 path mismatch失败；
   S_2 后、seam return前必须以相同 flags从 fixed absolute `repo_root` fresh
   reopen并要求 identity等于最初 pinned root。G6 另按第 9 节在 link前后重走
   ticket parent。

待创建而尚不存在的 Q/ticket/result/marker只验证 parent chain和 lexical name；
存在性规则由相应阶段单独校验。G6 使用无 pathname 的 `O_TMPFILE`，见第 9 节。

每值 exact `{path,sha256}`；`path` 是 safe repo-relative，`sha256` 是对应文件

```text
SHA256(_canonical_json_bytes(ImplementationSourceArtifactMapV1))
```

其中 `_canonical_json_bytes` 精确采用第 6 节规则。map 不增加独立文件或自由
顺序。pre-plan producer顺序唯一为：

```text
0. identity_core_binding_seed:
   take the profile-owned fixed core path plus the independent explicit
   expected_implementation_identity_core_raw_sha256;
   no-follow read once, compute observed raw SHA, require expected=observed,
   strict-parse ImplementationIdentityCoreV1 and construct the exact
   IdentityCoreBindingSeedV1;
   freeze parsed core five identity fields as IdentityCore_B.

1. source_observations:
   no-follow read the three already-existing files;
   make exact {path,raw_sha256} bindings.

2. SourceMap_seed:
   construct a new exact object from source_observations in the three-key
   schema above; it does not contain anchor, source-trace or future artifact.

3. implementation source trace:
   five identity fields := IdentityCore_B;
   core path/raw SHA
     := IdentityCoreBindingSeedV1.path/observed_raw_sha256;
   source_artifact_map_sha256
     := SHA256(canonical JSON of SourceMap_seed);
   write/freeze the source trace.

4. implementation anchor:
   first five anchor.identity fields := IdentityCore_B;
   bind the exact source-trace path/raw SHA in anchor.identity;
   write/freeze the anchor.

5. candidate_bound_artifacts:
   observe and strict-validate the complete §2.4 map, now including the
   already-existing core, source trace and anchor bindings;
   require candidate implementation_identity_core binding
     = {path: IdentityCoreBindingSeedV1.path,
        sha256: IdentityCoreBindingSeedV1.observed_raw_sha256}.

6. SourceMap_candidate:
   positive-project the exact three keys from candidate_bound_artifacts;
   require SourceMap_candidate = SourceMap_seed.

7. plan:
   plan.bound_artifacts := frozen deep copy(candidate_bound_artifacts);
   SourceMap_B := positive projection of plan.bound_artifacts;
   require SourceMap_B = SourceMap_candidate = SourceMap_seed.
```

`IdentityCoreBindingSeedV1`、`IdentityCore_B`、`SourceMap_seed` 与
`candidate_bound_artifacts` 是 typed in-memory observations，不是 plan字段；
core本身是 pre-anchor externally bound artifact。
因此没有“先有 anchor才知道 trace identity”或“先有 plan再验证 plan input”的
循环。loader verification从已经存在的 core、三个 source files、source
trace、anchor和 complete candidate重复上述 0–7；不写文件。

branch rules：

```text
accepted final-ticket verification:
  SourceMap_T := exact positive projection of TKT.bound_artifacts
  SourceMap_T = SourceMap_B = SourceMap_seed
  TKT.bound_artifacts.implementation_identity_core
    = candidate bound core binding
    = {path: IdentityCoreBindingSeedV1.path,
       sha256: IdentityCoreBindingSeedV1.observed_raw_sha256}
  TKT/anchor/source-trace five identity fields = IdentityCore_B
  SHA256(canonical JSON of SourceMap_T)
    = source trace source_artifact_map_sha256

rejected:
  validate SourceMap_seed/candidate/SourceMap_B only;
  TKT and SourceMap_T do not exist
```

构造 plan/Build/Q 之前，G5 pre-Q builder必须完成步骤 0–7。accepted loader在
TKT出现后执行 SourceMap_T 独立投影；等值由 `P(TKT)=Build` 间接且由本节
direct equality同时证明。任何分支都不得等待、预测或反向读取 future ticket。

## 6. Canonical encoding

所有 JSON：

```text
UTF-8 strict JSON types
duplicate keys rejected
NaN/Inf rejected
string keys
canonical: sort_keys=true,separators=(",",":"),ensure_ascii=false,no LF
pretty raw: indent=2,sort_keys=true,ensure_ascii=false,allow_nan=false,+ one LF
```

除明确写为 integer/bool/array/object 的字段外，所有字段均为 nonempty string；
所有 SHA 为 64 lowercase hex；integer 不接受 bool；所有 path 先通过各节规定的
safe root、lexical normalization、non-symlink、no-follow 规则。unknown/missing
field、duplicate array item 和替代 scalar representation 均拒绝。

ticket raw 必须与 pretty reserialization byte-identical。

ticket self digest：

1. 深复制 ticket；
2. 只将 `authorization.canonical_sha256` 置 64 个 `0`；
3. 对完整 ticket canonical JSON 取 SHA；
4. raw SHA 只由外部参数传入，不进入 ticket。

clearance、issuance、implementation identity/source trace、invocation、review
request 和 post-review trace 都没有 self-digest field。只按各 exact schema
枚举的字段存储 binding：Q/M/A/C 同时绑定 raw/canonical；implementation anchor、
implementation source trace和 Z 只存 raw binding。所有对象仍 strict parse并可
重算 canonical SHA，但未枚举的 canonical digest不声称被持久字段绑定。

## 7. 同一 private loader seam 与 G3 等价

实现唯一 private seam：

```text

  ticket_path,
  expected_authorization_sha256,
  expected_implementation_identity_core_raw_sha256,
```

## 9. Bearer 与 G6

stdin 只接受恰好 `64 lowercase hex + one LF + EOF`。大写、空白、额外 bytes、
argv/env token 均拒绝。token preimage 只在 live broker memory，G3/G4 accepted
后且 G5 request 前生成 commitment；本文件不授权现在生成。

byte domain 唯一定义：

```text
stdin_raw must have length 65
stdin_raw[0:64] must match ASCII [0-9a-f]{64}
stdin_raw[64:65] must equal b"\n"
the next read must return EOF
T := hex-decode(stdin_raw[0:64])      # exactly 32 raw bytes
single_use_token_sha256 := SHA256(T)  # lowercase hex digest
```

64-byte ASCII hex文本和结尾 LF 都不进入 commitment hash；public/private loader
接收的 `second_audit_token` 必须 exact 等于 32-byte `T`。

G6 namespace 唯一定义：

```text
ticket_raw_sha := SHA256(_pretty_json_bytes(TKT))
ticket_dir     := namespace_profile.ticket_path.parent
canonical_name:= namespace_profile.ticket_path.name
expected_size  := len(_pretty_json_bytes(TKT))
```

`canonical_name` 必须是单一 POSIX component，无 `/`、`.`/`..` 或 alternate
spelling。G6 不再创建 named temp，不执行 pathname cleanup，也不使用
hard-link-then-unlink。机制选择由已绑定 capability probe证明：

```text
O_TMPFILE open = PASS
AT_EMPTY_PATH direct link = FAIL ENOENT
/proc/self/fd/<fd> + linkat(..., AT_SYMLINK_FOLLOW) = PASS
linked inode identity equal = true
post-link nlink = 1
```

Linux constants/source path exact：

```text
AT_FDCWD          := -100
AT_SYMLINK_FOLLOW := 0x400
proc_source(tmp_fd)
  := ASCII bytes "/proc/self/fd/" + base-10 tmp_fd with no sign/padding
```

`/proc/self/fd` 必须存在；`proc_source` no-follow lstat必须是 symlink，followed
stat必须 exact 等于 `fstat(tmp_fd)`。若 O_TMPFILE、procfs或 linkat primitive
不可用/不匹配，fail closed；禁止 named-temp fallback。

production issuance只接受 production profile + accepted C；fixture profile只
允许同算法 fault tests，不释放 production bearer、不启动 history。G6 exact
state machine：

```text
S0 PINNED
  validate namespace profile leases per §0.1
  walk lexical ticket parent and pin ticket_dir identity D
  require canonical_name ENOENT

S1 UNNAMED_CREATED
  openat(ticket_dir_fd, ".",
    O_RDWR|O_TMPFILE|O_CLOEXEC, 0400) -> tmp_fd
  immediately fstat(tmp_fd)
  require regular, st_nlink=0, st_size=0
  created_identity := (st_dev,st_ino)

S2 UNNAMED_COMPLETE
  write exact pretty ticket bytes; reject short/extra write
  fsync(tmp_fd)
  require fstat regular, same created_identity, st_nlink=0,
    st_size=expected_size
  pread exact expected_size+1 and require exact raw bytes then EOF
  complete_identity := (st_dev,st_ino,expected_size)

S3 PRELINK_VERIFIED
  perform full Q/M/A/C/Z/projection/credential revalidation
  validate all profile leases and re-walk ticket parent
  require re-walk parent (st_dev,st_ino)=D
  require canonical_name ENOENT
  require tmp_fd still complete_identity, nlink=0 and exact raw bytes
  require proc_source lstat symlink and followed stat=complete_identity

S4 LINKED
  rc := libc.linkat(
    AT_FDCWD, proc_source(tmp_fd),
    ticket_dir_fd, canonical_name,
    AT_SYMLINK_FOLLOW)
  only rc=0 enters LINKED; any nonzero return enters the failure table below
  fsync(ticket_dir_fd)
  require tmp_fd and no-follow canonical are regular
  require both exact same complete_identity and st_nlink=1
  no-follow open/read canonical bytes; require raw/canonical/self digest exact

S5 CANONICAL_VERIFIED
  validate all profile leases and re-walk ticket parent
  require re-walk parent identity=D
  require canonical name resolves to complete_identity, st_nlink=1
  require canonical raw/canonical/self digest unchanged
  close tmp_fd; reopen canonical no-follow
  require same complete_identity, st_nlink=1 and exact bytes

S6 HANDED_OFF
  only after every S5 equality passes, call atomic custodian_accept(T)
  if it raises/fails, ownership did not transfer
  if it returns an already-prepared immutable acceptance receipt,
    ownership has transferred exactly once
  set released_to_custodian=true and directly return that receipt
```

custody invariant覆盖从 token generation 到 S6 handoff 的完整 broker lifecycle，
不是只在 G6 函数入口才安装：

```text
immediately before T is generated:
  released_to_custodian := false
  custody_destroyed := false
generate T only inside this outer custody guard

outer finally:
  if released_to_custodian is false:
    destroy broker custody first;
    record custody_destroyed=true;
  no filesystem assertion/close/re-walk exception may bypass this finally
```

该同一个 guard覆盖 token生成后 G5 request、accepted/rejected C、pre-G6
validation和 G6；不得在 G6 重新初始化 flag。rejected C、G5 exception或任何
pre-G6 return都必须在没有 canonical ticket写入的情况下先销毁 broker custody。

`custodian_accept(T)` 的 contract 是原子 ownership handoff：其内部所有可能失败
的 launch preparation必须在接受 T之前完成；失败/raise表示 custodian没有保留
T，成功只返回调用前已准备好的 immutable receipt。成功返回后，
`released_to_custodian=true` 是 S6 最后一个 state write；此后 G6不得再执行
launch、文件 I/O、hash、logging、allocation、assertion、cleanup或任何 protocol
state transition，唯一剩余动作是直接返回已有 receipt。此前任何 return/raise
均触发 broker destruction。

formal wrapper launch是 S6成功返回后由 custodian执行的外部 post-G6 phase，
不属于 G6 failure table。post-handoff launch failure不能追溯声称 broker仍可
销毁已转移 custody；它必须保留 canonical ticket、把该 authorization标为
poisoned、禁止复用 T/ticket并另开 issuance successor，不得在同一授权上 retry。

failure table：

```text
A0. rejection or any failure after T generation but before G6:
   outer custody guard destroys broker custody first
   no G6 state is entered and no canonical ticket is created

A. failure before linkat call, including S0 canonical preexistence:
   outer finally destroys custody first
   close tmp_fd if created
   validate leases/re-walk and observe canonical without touching it
   if close succeeded AND re-walk succeeded AND canonical is ENOENT:
     CLEAN_PRELINK_ABORT_NO_NAMESPACE
   else:
     AUTHORIZATION_NAMESPACE_POISONED

B. linkat rc != 0, including EEXIST:
   outer finally destroys custody first
   close tmp_fd
   validate leases/re-walk and observe canonical without touching it
   if close succeeded AND re-walk succeeded AND canonical is ENOENT:
     CLEAN_PRELINK_ABORT_NO_NAMESPACE
   else:
     AUTHORIZATION_NAMESPACE_POISONED
   if canonical exists and is same complete_identity, treat as
     AMBIGUOUS_COMMITTED_POISONED; preserve it
   if canonical exists and is any other identity, treat as
     FOREIGN_CANONICAL_COLLISION_POISONED; preserve it

C. linkat rc == 0 then any S4/S5/pre-accept handoff failure:
   outer finally destroys custody first
   close tmp_fd if open
   AUTHORIZATION_NAMESPACE_POISONED
   preserve canonical in its observed state
```

close、absence observation或re-walk本身失败只能把 clean abort升级为 poison，
不能跳过 custody destruction。任何 pre-accept failure branch均不能进入
`S6 HANDED_OFF`；S6 handoff成功后没有 G6 failure branch或 fallible G6 step。

这里没有 pathname unlink、rename或cleanup authority。`linkat rc=0` 是唯一
commit boundary；publisher永不删除、不覆盖 canonical，poison后另开 successor。
本 profile不声称对 canonical link创建后的 active malicious writer或 pre-marker
token复制提供 durable protection。
