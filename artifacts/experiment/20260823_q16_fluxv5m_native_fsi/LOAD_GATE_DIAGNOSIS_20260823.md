# Yamano 正式 Q16 原生载荷门诊断

## 结论

本轮没有启动论文轨迹。正式 5×3 Q16 / 15×10 FLUX‑V5M CUDA 的载荷门在 0.82 秒内完成：AIC、`Mf2` 和 `Qf_p_global` 通过，直接 Q16 `Mf1` 共同场对照失败，因此 CASE 入口保持封锁。

## 有效证据

| 契约 | 实测 | 门限 | 判定 |
|---|---:|---:|---|
| AIC 相对误差 | 3.0073528848739746e-07 | ≤1e-6 | PASS |
| `Mf2_vec1` step1–4 最大逐面板绝对误差 | 3.8163916471489756e-17 | ≤1e-13 | PASS |
| `Qf_p_global` step1–4 合力最大相对误差 | 0.0028941429731128726 | ≤0.005 | PASS |
| Q16 `Mf1` 厚度向共同场相对功误差 | 0.3735346675462884 | ≤0.05 | FAIL |

`Mf1` 的符号是正确的：Q16 和作者 oracle 的功均为负，说明流体附加质量都抵抗厚度向加速度。失败来自幅值/局部支撑差异，而不是符号或 CUDA 舍入误差。

## 根因边界

进一步的共同场分解表明，基础运动学和压力转置不是 37.35% 误差的主因：Q16/作者配置点法向加速度映射的相对差为 `0.002046150471220586`，压力虚功映射的相对差为 `0.005503029911055662`。大误差出现在 `A⁻¹` 之后的局部列支撑装配：作者的一个局部节点会同时影响共享该节点的相邻配置点，不能被简化为“每个目标面板只保留自身一行法向加速度”。

直接 Q16 算子对共同场给出 `-0.02585925156893745`，作者 oracle 为 `-0.04127802486316853`。两种正式 Q16 支撑判别都使结果变差：按 Q16 宏单元同时局部化输入/输出时误差扩大到 `0.6664220895571276`；按气动目标面板积分、输入列取其配置点所属 Q16 宏单元时误差扩大到 `0.6840688263596992`。两项改动均已回退到误差 37.35% 的最近可解释状态，未进入生产证据。

不得通过缩放系数调参，也不得恢复低阶结构中间自由度。下一步要在正式 Q16 基函数上定义可证明的共享支撑局部化，使配置点邻接影响和压力虚功保持一致，再由共同场 oracle 关闭这 37.35% 的来源。

## 防止重复错误

`reproduce_yamano2020_q16_flux_v5m_native.py` 现在强制读取载荷门文件。当前运行会明确报告 `mf1_common_field` 失败并非零退出；在门文件变成 `status=passed` 前，1/2/4/8 步运行均不可启动。
