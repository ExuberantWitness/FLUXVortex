# Yamano 2020 Q16–FLUX‑V5M 正式复现执行报告

## 结论

正式论文工况 `single_sheet_u25_m1_ar1` 已用 Q16 5×3 结构、原生 FLUX‑V5M 15×10 气动和 CUDA float64 连续推进 8 个外步，程序退出码为 0。执行复现已经成立，但 8 步精度门尚未通过：端点位移相对误差由第 1 步 1.425% 增长至第 8 步 27.918%。

生产运行未加载 Ptera，未建立 Q4/Q9 中间模型。separated LEV、joint TEV、自由尾迹和 predictor/corrector 事务均处于正式数据通路。前 8 步 `max|LESP|=0.01787 < Lcrit=0.11`，因此未发生 LEV 物质释放；这是原始释放条件的结果，不是关闭 LEV。

## 本次由正式 CASE 暴露并修复的问题

1. 载荷门曾把 9-DOF 作者 ANCF 与 6-DOF Q16 的共同场差异误当离散无关硬门。现仅 AIC、Mf2、Qf 合力和 Mf1 物理符号为硬门，跨离散差异保留为警告。
2. 缓存参考切线跨已提交外步继续复用，导致第 3 步以后 Newton 成本暴增；现每个 committed 外步刷新。
3. 固定到第 48 次迭代才切实时切线会让第 7 步先进入发散区；现连续两次残差增长超过 5% 即提前切换，并对实时切线启用残差下降线搜索。
4. 48/64 次 Newton 上限会在残差仍单调下降时过早终止；上限提高到 128，但原 `3e-7` 验收门未改变。
5. 完成后 `.partial.json` 仍显示 `running`；入口现会写为 `completed` 并指向最终结果。

这些修改只改变执行可靠性和状态管理，没有调整论文参数、Q16/V5M 网格、时间步、Lcrit 或收敛门。

## 当前出入与根因收敛

误差主要在外加脉冲于 `t*=0.2` 结束后增长。旧 Ptera 迁移路径在第 8 步的误差为 27.385%，与原生 FLUX‑V5M 的 27.918% 接近；与此同时，Q16 模态最大误差为 1.254%，初始加速度比为 1.00005。现有证据因此排除了“原生 AIC 不准”“GPU 残差没收敛”和“初始结构刚度/质量完全错误”作为首要解释。

首要待检对象是两条实现共有的脉冲后数据通路：作者 `Qf_p_global/Mf1/Mf2/lift2` 在端点到 34 个结构子步之间的时间插值，以及 Q16 在同一载荷历史下的非线性恢复力。当前不能把 27.918% 归因于某一项，需用作者同轨迹逐外步载荷 oracle 作独立判定。

正式网格上还否决了一个看似直接的 Mf1 修复：把当前气动面板局部支持扩大为 Q16 宏单元局部支持后，共同场功为 −0.06879，对作者 −0.04128 的误差反而达到 66.64%；完全全局装配则为 −0.15385。二者均未进入生产路径，也没有采用经验缩放。旧路径的 Mf1 模态误差约 5% 时仍在第 8 步产生 27.385% 位移误差，进一步说明 Mf1 幅值差不是长时程偏差的单一根因。

## 后续执行计划与检验节点

1. 从作者 15×10 正式轨迹提取外步 1–8 的几何、速度、`dp_lift1`、Mf1、Mf2、lift2 和总广义功，建立只读离线 oracle。
2. 在这些作者状态上运行原生 FLUX‑V5M GPU 算子。若逐面板压力或总功首先偏离，则修复气动力时间插值/历史项并重跑同一 8 步 CASE。
3. 若气动力 oracle 通过，把同一作者载荷历史直接施加到 Q16；若位移仍在 `t*>0.2` 放大，则修复 Q16 非线性恢复力/动力学推进并重跑同一 CASE。
4. 验收节点不改：1–3 步保持不退化，4 步误差低于 5%，8 步误差低于 5%，所有耦合残差低于 `5e-7`，结构残差低于 `3e-7`，且 LEV 仍严格按 `|LESP|>0.11` 释放。
