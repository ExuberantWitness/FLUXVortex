## 3. 未修复的缺陷：账本继承没有生效

代码里已经加了继承链路（`NativeV5MProposal.preconvected_retention` → `inherited_retention` → 复用分支把 cull 三项填进去），但**实测 payload 里 `particle_cull_count` 仍全为 0**：

| 步 | lvl0 cull | lvl0 粒子数 | lvl2 cull | lvl2 粒子数 |
|---|---|---|---|---|
| 99 | 0 | 26,425 | 0 | 26,427 |
| 100 | 0 | 26,696 | 0 | 26,698 |
| 101 | 0 | 26,967 | 0 | 26,969 |
| **102** | **250** | 26,773 | **0** | 26,775 |
| **103** | **270** | 26,722 | **0** | 26,724 |

粒子数差 2（剔除确实发生了），但计数报 0 ⇒ **继承代码路径没有把值带到被提交记录里**。可能是 `retention` 在提交链上被另一份记录覆盖，或 `preconvected_retention` 在迭代 1 时被置空。**未定位、未修复。**

影响范围：只要 flag 保持默认 0，生产路径不受影响。**启用前必须先修这条**，否则环量账本会静默漏记（`_advance_material_state` 的注释明确禁止 silent cap）。

## 4. 判定

- 速度：lvl2 相对 lvl0 **＋21.9%**，相对 lvl1 再 **＋10.3%**；省的是每步 2.98 次对流里的约 2 次。
- 稳定：耦合迭代数、提议数、formal replay 数、粒子数量级全部不变 ⇒ 收敛行为未变。
- 精度：1e-6 相对，比 lvl1 大但仍在模型自身误差的 1e-7 倍量级。
- 但账本缺陷未修 ⇒ **当前不适合作为默认路径**。
