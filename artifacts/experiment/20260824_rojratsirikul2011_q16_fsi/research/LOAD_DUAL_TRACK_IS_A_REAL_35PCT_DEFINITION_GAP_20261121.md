# ⑬ 前置测量：载荷双轨是**真实的 ~35% 定义分歧**，不是分解口径问题（2026-11-21）

> 工具：`platform/warp_vpm/diagnose_roj_load_decomposition.py`（本轮固化）
> 数据：A16、t*=0.03、1 个 shadow 样本（`SHADOW_RESOLVED_CADENCE=50`，但 `step==max` 也采样）
> 性质：**只读测量**；`q16_shadow_resolved_consumer.py` 是 audit-only 类（从不施加载荷），`case_runner` 只扩了证据汇总白名单

## 1. 要回答什么

⑬（载荷双轨统一）能否做成"保持分解的迁移"，取决于 `projection_quadrature_discrepancy = 0.28–0.52` 的性质：

- 若是**分解口径**问题（比较时漏了 velocity/Mf1 项）⇒ 把三项分别灌进对应槽位即可，工程量小；
- 若是**载荷本身**的分歧 ⇒ 需要判定"哪条轨道对"，是研究决策，不是工程清理。

## 2. 测量结果（同一分母 `|packet|`）

| 量 | 值 |
|---|---|
| `\|legacy constant\|` | 4.144e-4 |
| `\|packet 全量\|` | 3.838e-4 |
| `\|legacy const+vel+Mf1\|` | 2.866e-4 |
| `\|packet − constant\| / \|packet\|` | **0.338** |
| `\|packet − 三项和\| / \|packet\|` | **0.383** |
| `\|legacy velocity_force\|` | 1.13e-8（`\|constant\|` 的 2.7e-5，可忽略）|
| `\|legacy Mf1 action\|` | 1.341e-4（`\|constant\|` 的 **32.4%**）|
| 传输力闭合误差 | 3.10e-24 |
| 点级功共轭相对误差 | **0.0**（精确）|

## 3. 结论：我的一个推断被自己的数据推翻

我最初看到 `0.313 ≈ 0.324`（记录差异 ≈ Mf1 相对大小）时推断"差异就是被比较所省略的 Mf1 项，两条轨道其实一致"。**这个推断错了**：把 velocity + Mf1 加进去之后，与 packet 的距离从 0.338 变成 **0.383 —— 更远**。

⇒ **两条轨道是真实的载荷定义分歧，约 35%**，与分解口径无关；而**传输合同本身是精确的**（力闭合 3e-24、功共轭 0.0），所以分歧在载荷里，不在映射里。

## 4. 这对 ⑬ 意味着什么

⑬ 不是工程清理，而是**研究决策**：

1. 采用 packet（5P KJ + 非定常）会把结构看到的载荷改变约 **35%**；
2. 当前柔翼 `zmax/c = 0.0451`（实验 0.0434，+4%）是在**压力求积**轨道下取得的，换轨道后这个吻合**不再成立**，必须整体重推；
3. 因此**不能**用柔翼判据来裁决轨道：`(zmax, Cn)` 对"气动尺度 × 刚度尺度"是**退化**的（两者同乘一个因子可同时解释 0.0451 与 +34%），而 35% 的载荷改动正好落在这个退化方向上。

## 5. 建议的裁决路径（不碰退化）

用**已通过外部验证**的工况当裁判，而不是柔翼：

- **Yamano 载荷门**（`verify_yamano2020_q16_native_load_gates.py`，作者载荷复现）——直接检验两条轨道的载荷是否都对得上作者实现；
- **Izraelevitz Fig.14**（12 个俯仰-升沉工况的 CT，当前 MAE 0.0409 已验证）——推力对载荷定义敏感，可作为独立判别器。

做法：在**同一状态**上分别用两条轨道组装载荷，投影到 CT / Yamano 参考量，看哪条更接近外部真值。这是"用已知答案定标定义"的标准做法，且不依赖柔翼的退化对。

## 6. 边界
- 单工况、单时刻（A16, t*=0.03, 1 样本）；35% 是这一点的值，未做时间序列统计；
- `SHADOW_RESOLVED_CADENCE=50` 意味着长跑里每次只采少数样本；本测量依赖 `step==max_aero_steps` 的采样；
- 未改动任何生产数值；新增的证据键（`packet_full_vs_legacy_three_term_relative`、`constant_only_vs_packet_relative`、`packet_generalized_norm`、`legacy_three_term_norm`）只进 `resolved_load_evidence`，不影响求解。
